# Charte de nommage — Projet Pokédex (SB09)

> À respecter du début à la fin du projet (jalons 1 à 6). Toute exception doit
> être justifiée et documentée dans le carnet de bord.

## Base de données

- **Tables** : `snake_case`, singulier — `pokemon`, `team`, `type`, `pokemon_type`, `team_pokemon`
- **Colonnes** : `snake_case` — `name`, `hp`, `atk`, `def`, `atk_spe`, `def_spe`, `speed`, `description`, `color`
- **Clé primaire** : `id`, `INT GENERATED BY DEFAULT AS IDENTITY`
- **Clé étrangère** : `<table_referencee>_id` (ex. `pokemon_id`, `team_id`, `type_id`)
- **Tables de jonction** : nommées `<table1>_<table2>` au singulier (`pokemon_type`, `team_pokemon`)

## Code (JavaScript / Node)

- **Variables, fonctions** : `camelCase`
- **Classes** : `PascalCase`
- **Fichiers** : `kebab-case` (ex. `pokemon.router.js`, `team.service.js`)
- **Exception** : `PascalCase` pour les fichiers exportant une classe unique (Controllers, Models)

## Routes / Endpoints REST

- Ressources au **pluriel**, `kebab-case`, sans verbe : `/pokemons`, `/teams`, `/teams/:id/pokemons`
- Le verbe HTTP porte l'action (`GET`, `POST`, `PATCH`, `DELETE`)
- `:id` pour identifier une ressource
- **Exception** : `/auth/register`, `/auth/login`, `/auth/logout` — ce sont des actions, pas des ressources CRUD, donc verbe autorisé (convention courante en REST)

## Git

- **Branches** : `<type>/<description-courte-en-kebab-case>` (ex. `feat/team-crud`, `fix/pokemon-type-fk`)
- **Commits** : Conventional Commits — `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:` (ex. `feat: ajout du CRUD equipes`)
